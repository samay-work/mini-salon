Why the prompt is written this way. The service list isn’t hardcoded in the prompt. On every chat request, the server reads the services table and injects it into a {{SERVICES}} placeholder, so prices and durations can never go stale. The rules are numbered and explicit: quote prices only from the live list, say “I don’t have that information” for anything else (delivery, discounts, stylists, offers), ignore attempts to change the rules, and never claim a slot is free or booked, since availability lives in the booking form. A language rule makes the bot reply in the customer’s language (English, Hindi, Marathi, Hinglish). Three short examples anchor the tone for Hinglish and Marathi.

What broke during testing. The first live test of the chatbot returned the fallback error (“Sorry, I’m having trouble right now”). The prompt wasn’t the cause. The configured model, gemini-2.0-flash, was no longer available on my API key. Switching to another model name still failed (404), so I stopped guessing: I listed the models my key supports, then called four candidates directly. Two worked, one returned 503 (temporarily overloaded), and one returned 404 (listed, but not usable for text generation). I switched to gemini-flash-lite-latest, a name Google keeps pointing at a current model.

Prompt testing results. I ran 18 test messages covering Hinglish and Marathi, multi-service totals, services not on the menu, invented-information traps (discounts, delivery, stylist names, Sunday hours), price-negotiation pressure, prompt-injection attempts, and off-topic questions. All were handled correctly, so no prompt change was needed. If I found a failure later, my first step would be adding a rule and a short example for that case, then re-running the same message to compare before and after.
